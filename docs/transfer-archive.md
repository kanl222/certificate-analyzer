# Защищённый перенос на другое устройство

Реализация: `infrastructure/transfer_archive.py`. Это отдельный API,
пока без кнопок GUI, команд IPC и автоматического переключения профиля.

Архив включает согласованный снимок SQLite через backup API (включая WAL),
все файлы папки хранилища, файлы сертификатов и МЧД, на которые ссылается БД,
и карту путей. Сотрудники, заявки и история сохраняются вместе с остальной БД.
При недостающих файлах экспорт завершается ошибкой. Для сертификата допускается
доступная копия из управляемого хранилища или зарегистрированных источников.
Закрытые ключи из системного хранилища сертификатов не экспортируются.

Весь ZIP, включая имена файлов и БД, шифруется AES-256-GCM. Ключ получается
из пароля через scrypt (`N=131072`, `r=8`, `p=1`, случайная соль 16 байт).
Пароль минимум 12 символов; лучше использовать длинную уникальную парольную фразу.
Пароль не сохраняется. Без него восстановление невозможно. Формат версии 1
фиксирует параметры алгоритмов, а заголовок защищён аутентификацией.

## Порядок переноса

1. Остановить демон и закрыть GUI. Не запускать их до завершения экспорта:
   SQLite backup согласует БД, но не обеспечивает общий снимок БД и файлов.
   API отклоняет экспорт при наличии IPC-токена; это дополнительная проверка,
   а не блокировка от конкурентного запуска демона.
2. Создать архив. Передать пароль отдельно от файла.
3. На новом устройстве установить совместимую версию программы.
4. Восстановить архив в **новую** папку профиля. Слияние и перезапись
   существующего профиля не поддерживаются.
5. Запустить приложение с полученным `settings.json` через имеющийся
   параметр выбора конфигурации. Автоматический выбор восстановленного профиля
   пока не подключён.

```python
from pathlib import Path
from getpass import getpass
from certificate_analyzer.infrastructure.transfer_archive import export_archive, import_archive

export_archive(
    Path("/path/to/certificates.db"),
    Path("/path/to/certificates"),
    Path("/path/to/transfer.cat"),
    getpass("Пароль архива: "),
)

settings_path = import_archive(
    Path("/path/to/transfer.cat"),
    Path("/path/to/new-profile"),
    getpass("Пароль архива: "),
)
```

При импорте пароль и целостность проверяются до извлечения файлов. Принимаются
только ожидаемые имена, запрещены пути выхода из папки, дубликаты и сжатые ZIP.
Проверяется SQLite и версия схемы. Пути сертификатов, источников и МЧД
переписываются в восстановленной копии; исходная БД не изменяется.
Настройки создаются заново с локальными путями. Старые папки автоматического
импорта, путь телефонного справочника и параметры автозапуска не переносятся.
Исторические пути в журнале аудита остаются историческими значениями.

## Ограничения прототипа

- Архив до 128 МиБ и 10000 файлов; обработка в памяти, не потоковая.
- Временная копия БД и восстановленные файлы существуют на диске открытым текстом;
  временные папки удаляются штатно, гарантированного стирания носителя нет.
- В Windows ограничения доступа наследуются от папки пользователя; POSIX-права
  `0600` не заменяют Windows ACL. Используйте папку профиля своего пользователя.
- Импорт предназначен для доверенного архива и пароля: шифрование не доказывает
  авторство отправителя и не превращает чужую БД в безопасный источник.
- Для совместного использования с будущим шифрованием полей потребуется
  отдельно перенести ключ данных под паролем архива. Пока поля БД не шифруются,
  поэтому перенос DPAPI/Secret Service ключей не реализован.
- До подключения к приложению нужно добавить управление остановкой демона,
  выбор профиля и защиту от параллельного запуска, а также проверить перенос
  Windows ↔ Linux на реальных устройствах.

Документация: [scrypt](https://cryptography.io/en/50.0.0/hazmat/primitives/key-derivation-functions/)
и [SQLite backup](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup).
