# Защищённый перенос на другое устройство

Формат реализован в `infrastructure/transfer_archive.py`. Меню «Файл → Экспорт →
Экспорт защищённого архива» и «Файл → Импорт → Импорт защищённого архива»
использует `ArchiveService` через IPC. Все записи выполняет демон под общим
замком команд и мониторинга. GUI остаётся только читателем SQLite.

Экспорт открывает мастер: сертификаты → сотрудники → МЧД → пароль и сохранение.
На каждом шаге показан список записей с флажками, кнопками «Выбрать всё»
и «Снять выбор». Кнопки «Назад» и «Далее» сохраняют выбор.
Связанные с выбранными сертификатами сотрудники автоматически отмечены
и обозначены в списке. Остальных сотрудников можно выбрать отдельно.
Заявки, аудит и история уведомлений в пользовательский экспорт не входят.
Неотмеченные записи удаляются из временной копии БД,
после чего копия очищается VACUUM, чтобы исключённые данные не остались в страницах.

Импорт поддерживает «Добавить» и «Заменить». Перед изменениями автоматически
создаётся полный защищённый архив `before-import-*.cat` рядом с текущей БД,
с паролем импортируемого архива. Без успешной резервной копии импорт не выполняется.
При замене все текущие таблицы очищаются; категории, отсутствующие в архиве,
остаются пустыми. История уведомлений меняется только если включена в архив.

При добавлении сертификаты сопоставляются по SHA-256, МЧД — по уникальному
номеру, заявки — по номеру заявки. Сотрудники сопоставляются по СНИЛС, затем
ИНН, затем ФИО и подразделению; неоднозначность вызывает ошибку.
Существующие сертификаты и МЧД сохраняются. Для сотрудников и заявок окно
конфликтов показывает обе записи и предлагает сохранить текущую, использовать
входящую или пропустить обновление. «Пропустить» оставляет существующую запись
и связи с ней. ID сотрудников переназначаются, связи заявок и сертификатов
переносятся на новые ID. Повторные источники и одинаковые события аудита
не добавляются. История объединяется без дубликатов с лимитом 100 записей.

БД изменяется в одной транзакции с проверкой внешних ключей. При ошибке
изменения откатываются, восстановленные для операции файлы удаляются.
При успехе файлы сохраняются в `archive-imports/<идентификатор>/files` рядом
с текущей БД, пути в записях указывают на них. Старые физические файлы при
замене сохраняются. Просмотр конфликтов привязан к содержимому архива и
снимку данных: если они изменились, нужно повторить просмотр.

Архив включает согласованный снимок SQLite через backup API (включая WAL),
выбранные записи, относящиеся к ним файлы и карту путей.
Полная автоматическая резервная копия перед импортом сохраняет все данные,
включая заявки, аудит и историю. Импорт старых архивов остаётся совместимым.
При недостающих файлах экспорт завершается ошибкой. Для сертификата допускается
доступная копия из управляемого хранилища или зарегистрированных источников.
Закрытые ключи из системного хранилища сертификатов не экспортируются.

Весь ZIP, включая имена файлов и БД, шифруется AES-256-GCM. Ключ получается
из пароля через scrypt (`N=131072`, `r=8`, `p=1`, случайная соль 16 байт).
Пароль минимум 12 символов; лучше использовать длинную уникальную парольную фразу.
Пароль не сохраняется. Без него восстановление невозможно. Формат версии 1
фиксирует параметры алгоритмов, а заголовок защищён аутентификацией.

## Отдельный API для восстановления нового профиля

1. Остановить демон и закрыть GUI. Не запускать их до завершения экспорта:
   SQLite backup согласует БД, но не обеспечивает общий снимок БД и файлов.
   API отклоняет экспорт при наличии IPC-токена; это дополнительная проверка,
   а не блокировка от конкурентного запуска демона.
2. Создать архив. Передать пароль отдельно от файла.
3. На новом устройстве установить совместимую версию программы.
4. Вызов `import_archive` восстанавливает архив в **новую** папку профиля.
   Для добавления или замены текущих данных используйте меню приложения.
5. Запустить приложение с полученным `settings.json` через имеющийся
   параметр выбора конфигурации. Автоматический выбор восстановленного профиля
   пока не подключён.

```python
from pathlib import Path
from getpass import getpass
from certificate_analyzer.infrastructure.transfer_archive import export_archive, import_archive

export_archive(
    Path("/path/to/certificates.db"),
    Path("/path/to/certificates"),
    Path("/path/to/transfer.cat"),
    getpass("Пароль архива: "),
)

settings_path = import_archive(
    Path("/path/to/transfer.cat"),
    Path("/path/to/new-profile"),
    getpass("Пароль архива: "),
)
```

При импорте пароль и целостность проверяются до извлечения файлов. Принимаются
только ожидаемые имена, запрещены пути выхода из папки, дубликаты и сжатые ZIP.
Проверяется SQLite и версия схемы. Старые поддерживаемые схемы обновляются
в копии перед восстановлением; более новые отклоняются. Пути сертификатов, источников и МЧД
переписываются в восстановленной копии; исходная БД не изменяется.
Настройки создаются заново с локальными путями. Старые папки автоматического
импорта, путь телефонного справочника и параметры автозапуска не переносятся.
Исторические пути в журнале аудита остаются историческими значениями.

## Ограничения прототипа

- Архив до 128 МиБ и 10000 файлов; обработка в памяти, не потоковая.
- Временная копия БД и восстановленные файлы существуют на диске открытым текстом;
  временные папки удаляются штатно, гарантированного стирания носителя нет.
- В Windows ограничения доступа наследуются от папки пользователя; POSIX-права
  `0600` не заменяют Windows ACL. Используйте папку профиля своего пользователя.
- Импорт предназначен для доверенного архива и пароля: шифрование не доказывает
  авторство отправителя и не превращает чужую БД в безопасный источник.
- Для совместного использования с будущим шифрованием полей потребуется
  отдельно перенести ключ данных под паролем архива. Пока поля БД не шифруются,
  поэтому перенос DPAPI/Secret Service ключей не реализован.
- Операции через меню сериализованы демоном. Отдельный офлайн-API требует
  остановки демона. Перенос Windows ↔ Linux ещё нужно проверить на реальных устройствах.

Документация: [scrypt](https://cryptography.io/en/50.0.0/hazmat/primitives/key-derivation-functions/)
и [SQLite backup](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup).
