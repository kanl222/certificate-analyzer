# Хранилище сертификатов и анализатор МЧД

**Certificate Analyzer** — настольное приложение для Windows и Linux, предназначенное для учёта сертификатов X.509, контроля сроков их действия и работы с машиночитаемыми доверенностями (МЧД). Оно помогает вести реестр сертификатов организации, находить владельцев и их контакты, отслеживать заявки на выпуск сертификатов и готовить отчёты.

Приложение предоставляет графический интерфейс на Tkinter, команды CLI для автоматизации и фоновый мониторинг. Данные хранятся локально: отдельный сервер базы данных не требуется.

## Возможности

- **Сертификаты:** импорт файлов CER/CRT/DER/PEM и каталогов, распознавание X.509, устранение дубликатов по SHA-256, просмотр владельца, издателя и сроков действия. Доступны поиск, фильтры по статусу и датам, сортировка и постраничный просмотр.
- **Заявки:** создание заявок на сертификаты, выбор сотрудника, изменение статуса и привязка выпущенного сертификата. Завершённые заявки отмечаются как обработанные и сохраняются в базе.
- **Сотрудники и контакты:** справочник сотрудников с подразделениями и контактными данными, загрузка телефонного справочника из TXT/DOCX и обновление контактов в записях сертификатов.
- **МЧД:** отдельная вкладка для импорта XML и сканирования каталогов, поиска и фильтрации доверенностей, просмотра данных представителей и полномочий, обнаружения повторяющихся представителей и экспорта в Excel. Объединение доверенностей формирует XML-черновик.
- **Отчёты:** экспорт реестра сертификатов в Excel и PDF с учётом выбранных условий, статистика и отчёт фонового мониторинга.
- **Мониторинг:** периодическая проверка сроков и наличия файлов в хранилище, уведомления о сертификатах, требующих внимания. Порог предупреждения и интервал проверок задаются в настройках.

В основном окне четыре вкладки: **Сертификаты**, **Заявки**, **Сотрудники** и **МЧД**. Для начала работы импортируйте сертификаты, при необходимости загрузите контакты, затем настройте срок предупреждения об истечении. Для автоматических проверок запустите worker или установите службу мониторинга по инструкции ниже.

SQLite хранит **записи и метаданные**, а сами файлы сертификатов находятся в отдельной папке. Для сертификата сохраняются SHA-256, владелец, издатель, сроки, контакты, имя исходного файла и путь в хранилище. Работа с БД построена на SQLAlchemy-моделях и репозиториях.

## Запуск

Python 3.11+, установленный Tkinter для GUI:

```sh
uv sync --extra gui
uv run certificate-analyzer
```

В окне доступны импорт отдельных файлов и папки, поиск, фильтры статуса/дат, сортировка, страницы по 100 записей, детали сертификата, удаление записей, справочник и отчёты. Двойной щелчок открывает файл сертификата. Импорт и отчёты выполняются в фоне; интерфейс обновляется в главном потоке Tk.

На Linux нужен шрифт с кириллицей (Noto Sans); для PDF — Arial, Noto Sans или DejaVu Sans. Windows-зависимости службы и уведомлений устанавливаются через `uv sync --extra gui --extra windows`.

GUI не сканирует исходные папки при открытии. На первом запуске импортируйте сертификаты кнопками **Импорт файлов** или **Импорт папки**. Дальше список загружается из SQLite.

## Импорт и файлы

- Поддерживаются CER/CRT/DER/PEM; импорт папки рекурсивный.
- Сертификат проверяется парсером X.509. Публичная часть сохраняется в DER-файл `<SHA256>.cer` в папке хранилища. Исходник не изменяется; блоки закрытых ключей из PEM не копируются.
- Файлы с одинаковым сертификатом, в том числе PEM и DER, соответствуют одной записи. Одинаковые имена разных сертификатов не конфликтуют.
- Файл публикуется целиком через временный файл; существующий файл с другим содержимым не перезаписывается.
- Повторный импорт неизменённых файлов пропускает X.509-парсинг после проверки хешей исходника и файла хранилища.
- Пропавший файл хранилища восстанавливается повторным импортом исходника. Повреждённый файл даёт явную ошибку.
- Удаление записи сохраняет исходник и файл в хранилище. Для восстановления записи импортируйте файл повторно.
- Файловая система и SQLite не образуют общую транзакцию. Если запись в БД прервётся после копирования, файл может остаться без записи. Повторный импорт папки хранилища восстанавливает такие записи без дублирования.
- Импорт фиксируется пакетами по 200 файлов. Ошибки отдельных файлов возвращаются отдельно; ошибка БД откатывает текущий пакет, ранее завершённые пакеты сохраняются.

## CLI

```sh
# Импорт в управляемую папку с сохранением записей в SQLite
uv run certificate-analyzer import /path/to/cert.pem /path/to/folder
uv run certificate-analyzer import /path/to/folder --phonebook phones.docx

# Указать свои пути (глобальные параметры до команды)
uv run certificate-analyzer --database /data/certificates.db --storage-folder /data/certificates import /incoming

# Запросы к БД, без сканирования файлов
uv run certificate-analyzer list --search Иванов --limit 100 --offset 0
uv run certificate-analyzer list --status EXPIRING_SOON --sort valid_to
uv run certificate-analyzer list --from-date 2026-09-01 --to-date 2026-12-31
uv run certificate-analyzer stats
uv run certificate-analyzer export report.xlsx --status EXPIRED
uv run certificate-analyzer export report.pdf --search Иванов
uv run certificate-analyzer delete SHA256_FINGERPRINT

# Мониторинг существующих записей
uv run certificate-analyzer worker --once
uv run certificate-analyzer --config /path/to/settings.json worker

# МЧД остаются отдельным XML-сценарием
uv run certificate-analyzer mchd /path/to/xml --output mchd.xlsx
uv run certificate-analyzer merge first.xml second.xml --output draft.xml
```

`scan папка` сохранён как CLI-команда импорта папки и поддерживает `--output report.xlsx`, `--phonebook`, а `scan папка --mchd` — анализ XML. Внутреннего старого Core/двухэтапного scan+parse больше нет.

Команды возвращают JSON в stdout; логи и ошибки — в stderr. Коды выхода: 0 — успех, 1 — ошибки части файлов/отсутствующие файлы хранилища при мониторинге, 2 — ошибка операции или конфигурации.

## Настройки

Основной файл: `~/.certificate-analyzer/settings.json`. Переменная `CERTIFICATE_ANALYZER_HOME` задаёт отдельный профиль (настройки, новая БД и папка сертификатов). Параметр `--config` поддерживается и GUI, и CLI; сам по себе он меняет только путь конфигурации, для отдельного профиля задавайте также пути хранилища/БД либо переменную окружения.

```json
{
  "database_path": "/data/certificates.db",
  "storage_folder": "/data/certificates",
  "export_folder": "/data/reports",
  "phonebook_path": null,
  "warning_days": 60,
  "check_interval": 604800
}
```

Если пути не заданы, новая БД — `~/.certificate-analyzer/certificates.db`, файлы — `~/.certificate-analyzer/certificates/`. Без отдельного профиля приложение сначала ищет прежнюю БД `~/.local/share/certificate-analyzer/certificates.db`, чтобы не потерять ранее сохранённые записи.

Изменения путей через окно настроек применяются после перезапуска. Существующие файлы автоматически не перемещаются: их абсолютные пути остаются в записях. Новые импорты используют новую папку.

Старое поле `folders` принимается для чтения прежней конфигурации, но не запускает автоматическое сканирование. Справочник TXT/DOCX загружается явно; контакты существующих записей обновляются в БД. Отсутствие старого исходника сертификата или справочника не мешает открывать сохранённые записи.

## База и архитектура

- Существующий слой `infrastructure/database`: SQLAlchemy engine и фабрика коротких сессий, принадлежащие контейнеру приложения. Нет глобальной сессии, файловых операций при импорте модуля и передачи сессии между потоками.
- Существующие таблицы `certificates`/`employees` сохраняются. Метаданные сертификата дополнены снимком контактов; `certificate_sources` связывает пути импорта и хеши с отпечатком.
- Аддитивная миграция через SQLAlchemy, версия схемы в `PRAGMA user_version`. Перед миграцией старой таблицы создаётся согласованная SQLite-копия рядом с БД: `*.YYYYMMDDHHMMSSffffff.bak`.
- Старые контакты и пути сохраняются. Если прежний репозиторий уже потерял путь, восстановить его из метаданных невозможно: импортируйте исходный сертификат повторно.
- Пакетные UPSERT, индекс срока действия, поиск с нормализацией кириллицы, SQL-сортировка/фильтрация/пагинация. Статусы вычисляются при чтении по текущему UTC; данные не устаревают из-за сохранённого вчера статуса.
- WAL, внешние ключи, ограниченное ожидание блокировок; запись пакета в транзакции. Дубликаты определяются SHA-256 публичного сертификата.
- `CertificateService` используется GUI, CLI и worker. Единственный формат представления — `CertificateDTO`; старые Core, контроллеры с файловым кешем и дублирующий presenter удалены.
- Из основных зависимостей убраны неиспользуемые PySide6, matplotlib, tkcalendar и pyperclip. GUI использует Tkinter, для окна МЧД pyperclip доступен в extra `gui`.

Сертификат с будущей датой начала недействителен на момент проверки; порог истечения задаётся `warning_days`. Проверяются поля и сроки, а не цепочка доверия/OCSP/CRL. Объединение МЧД создаёт неподписанный XML-черновик.

## Мониторинг и службы

Worker читает записи БД, пересчитывает сроки, формирует `monitoring.xlsx`, проверяет наличие файлов и отправляет уведомления. Исходные каталоги не сканируются. Linux-уведомления используют `notify-send`; Windows — `win10toast`.

**Linux:**

- Установка: `bash packaging/linux/install.sh` автоматически проверяет и устанавливает необходимые системные зависимости (`notify-send` из `libnotify`/`libnotify-bin`, `python3-tk`, `xdg-utils`, `gio`/`trash-cli`, шрифты) через пакетный менеджер (apt, dnf, pacman, zypper, apk), создает ярлык приложения `.desktop` и настраивает пользовательскую службу systemd. Флаги: `--deps-only` (только зависимости), `--no-deps` (без пакетов), `--service-only` (только служба), `--desktop-only` (только ярлык).
- Удаление: `bash packaging/linux/uninstall.sh` останавливает и отключает службу systemd, удаляет ярлык приложения (дополнительный флаг `--purge` очищает данные и настройки в `~/.certificate-analyzer`).

**Windows:**

- Полная установка: в PowerShell запустите `.\packaging\windows\install.ps1` (устанавливает зависимости GUI/Windows, создаёт ярлыки на рабочем столе и в меню «Пуск», регистрирует и запускает службу). Параметры: `-NoService` (без службы), `-ServiceOnly` (только служба), `-NoShortcuts` (без ярлыков).
- Управление только службой: `.\packaging\windows\install-service.ps1` (установка и старт службы от имени администратора) и `.\packaging\windows\uninstall-service.ps1` (остановка и удаление).
- Удаление: `.\packaging\windows\uninstall.ps1` (останавливает/удаляет службу и ярлыки, ключ `-Purge` удаляет данные из `%USERPROFILE%\.certificate-analyzer`).
- Настройки службы принадлежат её учётной записи; при необходимости задайте переменную `CERTIFICATE_ANALYZER_HOME`.

## Сборка установщика Windows

Для сборки нужен Windows, `uv` и Inno Setup 6. Одна команда создаёт автономное приложение PyInstaller, а затем установщик:

```powershell
.\packaging\windows\build-installer.ps1
```

Результаты:

- `dist\CertificateAnalyzer\` — переносимый каталог приложения;
- `dist\installer\CertificateAnalyzer-<версия>-Setup.exe` — установщик.

Если Inno Setup ещё не установлен, можно собрать только переносимый каталог:

```powershell
.\packaging\windows\build-installer.ps1 -BundleOnly
```

Установщик добавляет ярлык в меню «Пуск», предлагает ярлык рабочего стола и по умолчанию регистрирует автоматически запускаемую службу мониторинга. Для установки службы и записи в `Program Files` запрашиваются права администратора. Пользовательская БД и настройки в `%USERPROFILE%\.certificate-analyzer` при обновлении и обычном удалении не стираются.

## Сборка DEB-пакета для Linux

DEB-пакет предназначен для Debian-совместимых дистрибутивов Linux. Сборка выполняется в Linux той же архитектуры, что и целевая система; совместимость пакета зависит от версий системных библиотек. Для других дистрибутивов используйте запуск из исходников и скрипт `packaging/linux/install.sh`, описанные выше.

Для сборки нужны `uv` и `dpkg-deb` (`dpkg-dev`). Скрипт использует Python 3.11 и включает интерпретатор в автономное приложение:

```bash
bash packaging/linux/build-deb.sh
```

Скрипт определяет архитектуру `amd64`/`arm64`, собирает автономное приложение с Python и создаёт:

```text
dist/linux/certificate-analyzer_<версия>_<архитектура>.deb
```

Установка и удаление:

```bash
sudo apt update
sudo apt install fonts-noto-core
sudo apt install ./dist/linux/certificate-analyzer_0.1.0_amd64.deb
sudo apt remove certificate-analyzer
```

Приложение устанавливается в `/opt/certificate-analyzer`, команда — в `/usr/bin/certificate-analyzer`, ярлык — в системное меню приложений. Пользовательская служба мониторинга включается глобально и запускается при следующем входе пользователя. Для немедленного запуска:

```bash
systemctl --user daemon-reload
systemctl --user start certificate-analyzer.service
```

Пользовательские настройки и БД в `~/.certificate-analyzer` при удалении пакета сохраняются.

## Проверки

```sh
uv run pytest
uv run ruff check src tests --select F
CERTIFICATE_ANALYZER_GUI_TEST=1 uv run --extra gui pytest tests/integration/test_gui.py -q
uv build
```

Тесты используют временные БД и синтетические сертификаты, не пользовательское хранилище. GUI-тест проверяет фоновый импорт, загрузку из БД, поиск/статус, выбор записи и настройки. Windows Service требует отдельной проверки на Windows.
