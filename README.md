# Certificate Analyzer

Настольное приложение для Windows и Linux: учёт сертификатов X.509, контроль сроков действия, заявки на выпуск сертификатов, справочник сотрудников и работа с машиночитаемыми доверенностями (МЧД).

Приложение предоставляет интерфейс на Tkinter, команды CLI и фоновый процесс мониторинга. Данные хранятся локально в SQLite; отдельный сервер БД не требуется.

## Возможности

- Импорт сертификатов CER, CRT, DER и PEM: отдельные файлы или папка с подпапками. Дубликаты определяются по SHA-256 публичного сертификата.
- Поиск, фильтры по срокам и статусу, сортировка, просмотр владельца, издателя и контактов.
- Справочник сотрудников, импорт контактов из TXT/DOCX.
- Заявки на сертификаты: создание, изменение статуса, привязка сертификата, отметка «Обработана».
- Импорт XML МЧД, просмотр представителей и полномочий, фильтрация, экспорт и объединение в XML-черновик.
- Экспорт отчётов в Excel и PDF, журнал аудита и история уведомлений.
- Фоновая проверка сроков и наличия файлов, отчёт `monitoring.xlsx`, системные уведомления.
- Меню «Служба» для управления фоновым процессом и его автозапуском в Windows/Linux.
- Защищённый архив с выбором категорий данных; импорт с добавлением или заменой,
  резервной копией и разрешением конфликтов сотрудников и заявок.

Архивы доступны через «Файл → Импорт / Экспорт». Подробности и ограничения:
[перенос данных](docs/transfer-archive.md). При замене категории, не включённые
в архив, останутся пустыми. Пароль архива нужен и для автоматически созданной
резервной копии; не теряйте его.

## Установка в Windows

### Готовый установщик

1. Скачайте `CertificateAnalyzer-<версия>-Setup.exe` из [релизов проекта](https://github.com/kanl222/certificate-analyzer/releases), если установщик опубликован для выбранной версии.
2. Запустите установщик от обычного пользователя. Приложение устанавливается в `%LOCALAPPDATA%\Certificate Analyzer`; права администратора не требуются.
3. Оставьте включённым пункт «Запускать фоновый мониторинг при входе пользователя», если нужен автозапуск.
4. Откройте приложение через меню «Пуск» или ярлык рабочего стола, если выбрали его создание.

Python и инструменты разработки для готовой сборки не нужны. При выбранном автозапуске установщик сразу запускает фоновый процесс и добавляет его в HKCU Run. После закрытия окна мониторинг продолжает работать. Если автозапуск не выбран, GUI запускает процесс при открытии.

### Установка из исходников

Нужны Git, Python 3.11+ с Tkinter и `uv`. Выполняйте команды в PowerShell из каталога проекта:

```powershell
git clone https://github.com/kanl222/certificate-analyzer.git
cd certificate-analyzer
uv sync --extra gui --extra windows
uv run certificate-analyzer gui
```

Для создания ярлыков и включения автозапуска:

```powershell
.\packaging\windows\install.ps1
```

Параметры сценария:

| Параметр | Назначение |
|---|---|
| `-NoService` | Не настраивать автозапуск демона |
| `-ServiceOnly` | Настроить только демон; окружение `.venv` уже должно существовать |
| `-NoShortcuts` | Не создавать ярлыки |
| `-Help` | Показать справку |

Названия `Service` в параметрах сохранены для совместимости. Новая версия не устанавливает Windows-службу под LocalService: фоновый процесс работает в сессии текущего пользователя.

## Установка в Linux

Для графического интерфейса нужна рабочая графическая сессия. Для автозапуска из меню нужен пользовательский systemd. Без systemd приложение можно запускать вручную, но управление автозапуском покажет ошибку.

### DEB-пакет: Debian, Ubuntu и совместимые системы

Скачайте DEB-пакет из [релизов проекта](https://github.com/kanl222/certificate-analyzer/releases), если он опубликован. Выберите архитектуру вашей системы: `amd64` или `arm64`. В каталоге с одним скачанным пакетом выполните:

```bash
sudo apt install ./certificate-analyzer_*.deb
certificate-analyzer gui
```

Пакет содержит приложение и интерпретатор Python. Системные зависимости устанавливает пакетный менеджер. Приложение располагается в `/opt/certificate-analyzer`, команда — `/usr/bin/certificate-analyzer`, ярлык появляется в меню приложений.

DEB включает пользовательскую службу `certificate-analyzer.service` глобально: она запускается при следующем входе пользователя. Для запуска в текущей сессии:

```bash
systemctl --user daemon-reload
systemctl --user start certificate-analyzer.service
systemctl --user status certificate-analyzer.service
```

Запускайте эти команды от своего пользователя, без `sudo`. DEB должен быть собран для подходящей архитектуры и совместимой Linux-системы.

### RPM-пакет: ALT Linux, Fedora, Red Hat Enterprise Linux, Rocky Linux, AlmaLinux, РЕД ОС, openSUSE

Скачайте RPM-пакет из [релизов проекта](https://github.com/kanl222/certificate-analyzer/releases), если он опубликован. Выберите архитектуру вашей системы: `x86_64` или `aarch64`. В каталоге со скачанным пакетом выполните:

```bash
# Fedora / RHEL / Rocky Linux / AlmaLinux / РЕД ОС
sudo dnf install ./certificate-analyzer-*.rpm

# openSUSE
sudo zypper install ./certificate-analyzer-*.rpm

# ALT Linux: используйте сборку с релизом alt1
sudo apt-get update
sudo apt-get install ./certificate-analyzer-*-alt1.*.rpm

# Запуск приложения
certificate-analyzer gui
```

Пакет содержит приложение и интерпретатор Python. Приложение располагается в `/opt/certificate-analyzer`, команда — `/usr/bin/certificate-analyzer`, ярлык появляется в меню приложений.

RPM включает пользовательскую службу `certificate-analyzer.service` глобально: она запускается при следующем входе пользователя. Для запуска в текущей сессии:

```bash
systemctl --user daemon-reload
systemctl --user start certificate-analyzer.service
systemctl --user status certificate-analyzer.service
```

Запускайте эти команды от своего пользователя, без `sudo`. RPM должен быть собран для подходящей архитектуры и совместимой Linux-системы.

### Установка из исходников

Нужны Git, Python 3.11+, `uv`, Tkinter и системные компоненты уведомлений/открытия файлов. Из каталога проекта:

```bash
git clone https://github.com/kanl222/certificate-analyzer.git
cd certificate-analyzer
bash packaging/linux/install.sh --deps-only
uv sync --extra gui
uv run certificate-analyzer gui
```

Сценарий `--deps-only` устанавливает системные зависимости через доступный пакетный менеджер; для установки пакетов могут понадобиться права администратора. Он не устанавливает само Python-приложение — это делает `uv sync`.

Для ярлыка в меню приложений и автозапуска текущего пользователя:

```bash
bash packaging/linux/install.sh --desktop-only
uv run certificate-analyzer autostart enable
```

Автозапуск также можно включить в меню «Служба». Включение автозапуска не запускает новый процесс немедленно; используйте пункт «Запустить» либо откройте GUI.

Полный вызов `bash packaging/linux/install.sh` устанавливает системные зависимости, создаёт ярлык и включает/запускает пользовательскую службу `certificate-analyzer.service`. Само приложение должно быть установлено заранее. При обновлении скрипт отключает прежнюю службу `cert-analyzer.service`, если она существует.

Дополнительные параметры сценария: `--no-deps`, `--service-only`, `--desktop-only`, `--no-service`, `--no-desktop`, `--help`.

## Первое использование

1. Откройте вкладку «Сертификаты» и импортируйте файлы или папку. При открытии GUI исходные каталоги автоматически не сканируются.
2. При необходимости загрузите телефонный справочник TXT/DOCX и заполните сотрудников.
3. Во вкладке «Заявки» создавайте заявки и связывайте их с выпущенными сертификатами. Статус «Обработана» сохраняет запись для истории.
4. Во вкладке «МЧД» импортируйте XML доверенностей.
5. Откройте «Файл → Настройки» и задайте пути, порог предупреждения и интервал проверок.

Настройки разделены на вкладки «Хранилище», «Импорт», «Мониторинг» и «Отчёты». Для выбора путей доступны кнопки «Обзор…».

После изменения настроек остановите фоновый процесс через меню «Служба» и перезапустите приложение. Существующие файлы и БД автоматически не перемещаются.

## Фоновый процесс и автозапуск

Меню «Служба» доступно на обеих платформах:

- «Запустить», «Остановить», «Перезапустить».
- «Проверить состояние».
- «Журнал службы…» — просмотр общего журнала внутри приложения с автоматическим обновлением.
- «Включить автозапуск при входе», «Отключить автозапуск при входе».

Остановка оставляет GUI открытым для чтения. Создание, изменение и удаление данных недоступны до повторного запуска процесса. Закрытие GUI само по себе не останавливает мониторинг.

В Windows автозапуск использует реестр текущего пользователя HKCU Run. В Linux — пользовательскую службу systemd в `$XDG_CONFIG_HOME/systemd/user` или `~/.config/systemd/user`. Отключение в Linux маскирует службу для текущего пользователя, в том числе при глобальном включении DEB-пакетом. Пользовательский файл службы перед маскированием сохраняется рядом с суффиксом `.disabled.<время>`.

Для установленного приложения команды одинаковы в Windows/Linux:

```text
certificate-analyzer worker
certificate-analyzer worker --once
certificate-analyzer worker --stop
certificate-analyzer autostart enable
certificate-analyzer autostart disable
```

`worker` запускает непрерывный мониторинг в текущем процессе; при запуске в терминале команда остаётся работающей. `worker --once` запрашивает один цикл у демона, `worker --stop` останавливает его. Из исходников добавляйте `uv run` перед командой.

В Windows-сборке для консольных команд используйте `certificate-analyzer-cli.exe` из папки установки.

Мониторинг читает сохранённые записи, проверяет сроки и наличие файлов, формирует `monitoring.xlsx` в папке отчётов и отправляет уведомления. Исходные папки он не импортирует. Уведомления используют `win10toast` в Windows и `notify-send` в Linux.

## Данные и конфигурация

Каталог профиля по умолчанию:

| Windows | Linux |
|---|---|
| `%USERPROFILE%\.certificate-analyzer` | `~/.certificate-analyzer` |

В нём находятся `settings.json`, новая БД `certificates.db`, папка файлов `certificates/` и журнал `application.log`. Папка отчётов по умолчанию — `CertificateReports` в домашнем каталоге. Переменная `CERTIFICATE_ANALYZER_HOME` задаёт другой каталог профиля.

Без отдельного профиля приложение также проверяет наличие прежней БД `~/.local/share/certificate-analyzer/certificates.db` и использует её, если она найдена.

Параметр `--config` выбирает файл настроек; сам по себе он не меняет каталог профиля. Глобальные параметры ставятся перед командой:

```text
certificate-analyzer --config /path/settings.json gui
certificate-analyzer --config /path/settings.json autostart enable
certificate-analyzer --database /path/certificates.db --storage-folder /path/certificates gui
```

Пример настроек для Linux; в Windows используйте свои абсолютные пути с `/` либо экранируйте обратные слеши в JSON:

```json
{
  "database_path": "/home/user/.certificate-analyzer/certificates.db",
  "storage_folder": "/home/user/.certificate-analyzer/certificates",
  "export_folder": "/home/user/CertificateReports",
  "phonebook_path": null,
  "mchd_folder": "/home/user/MCHD",
  "folders": {
    "Сотрудники": "/home/user/Certs",
    "Руководство": "/home/user/ImportantCerts"
  },
  "warning_days": 60,
  "check_interval": 604800
}
```

Интервал указан в секундах: `604800` — одна неделя. Поле `folders` хранит пути, но не включает автоматический импорт.

GUI и демон должны использовать один абсолютный путь БД. Если демон уже запущен с другими параметрами хранилища или мониторинга, сначала остановите его, затем запустите приложение с нужной конфигурацией.

## Импорт и удаление

Сертификаты хранятся отдельно от SQLite: публичная часть копируется в DER-файл `<SHA256>.cer`. Исходники не изменяются, закрытые ключи из PEM не копируются и не сохраняются приложением.

Повторный импорт одинакового сертификата не создаёт дубликат записи. Импорт выполняется пакетами по 200 файлов; ошибки отдельных файлов возвращаются отдельно. При ошибке текущего пакета ранее завершённые пакеты сохраняются.

«Удалить из учета» удаляет запись, сохраняя файлы. «Удалить физический файл» удаляет выбранный файл и связанную запись учёта. Для восстановления учёта можно повторно импортировать сохранившийся сертификат.

Файлы и SQLite не образуют общую транзакцию: при сбое после копирования файл может остаться без записи. Повторный импорт позволяет восстановить учёт.

## CLI

Примеры для установленного приложения; при работе из исходников добавляйте `uv run`:

```bash
certificate-analyzer import /path/cert.pem /path/folder
certificate-analyzer import /path/folder --phonebook /path/phones.docx
certificate-analyzer scan /path/folder --output report.xlsx
certificate-analyzer list --search Иванов --limit 100 --offset 0
certificate-analyzer list --status EXPIRING_SOON --sort valid_to
certificate-analyzer stats
certificate-analyzer export report.xlsx --status EXPIRED
certificate-analyzer export report.pdf --search Иванов
certificate-analyzer delete SHA256_FINGERPRINT
certificate-analyzer mchd /path/xml --output mchd.xlsx
certificate-analyzer merge first.xml second.xml --output draft.xml
certificate-analyzer --help
```

Команда `mchd` и `scan --mchd` анализируют XML и могут экспортировать отчёт; импорт МЧД в БД доступен в GUI. При необходимости CLI автоматически запускает демон. Устаревшая команда `service` удалена; для управления демоном используйте `worker` и `autostart`.

Команды работы с данными выводят JSON в stdout; ошибки и журналирование — в stderr. Коды завершения: `0` — успех, `1` — частичные ошибки, `2` — ошибка запуска, конфигурации или операции.

## Архитектура хранения

Фоновый процесс — единственный writer в штатных сценариях. Он выполняет миграции и все изменения SQLite. GUI и CLI-клиенты открывают БД только для чтения (`mode=ro`, `query_only=ON`). Команды записи передаются через локальный JSON API на `127.0.0.1`, с токеном доступа и явным списком разрешённых методов.

После записи демон возвращает результат, созданные ID и ошибки; GUI обновляет данные из БД. При недоступности процесса показывается ошибка, самостоятельной записи из GUI нет. После обрыва связи команда не повторяется автоматически: она могла завершиться, поэтому перед повтором проверьте данные.

SQLite использует WAL для параллельного чтения. Второй штатный writer для того же пути БД отклоняется до открытия базы. Блокировки файлов для синхронизации обычных записей в БД не используются.

Общий журнал использует ConcurrentRotatingFileHandler: 5 MiB на файл и три резервные копии. Межпроцессная блокировка логгера относится только к журналу. Низкоуровневая фабрика `create_application(read_only=False)` предназначена для демона и изолированных тестов.

В журнал записываются запуск/остановка демона, изменения автозапуска, начало и результат мониторинга, выполнение IPC-команд и ошибки с трассировкой. Каждая запись содержит время, уровень, PID и имя компонента. Токены и аргументы команд не журналируются. Окно «Служба → Журнал службы…» показывает последние 256 КиБ `application.log`, обновляется каждые две секунды и доступно даже при остановленном демоне.

## Обновление и удаление

Перед обновлением остановите демон и закройте GUI. Для резервной копии при остановленном приложении сохраните каталог профиля, папку отчётов и все отдельно настроенные пути БД/хранилища. Это также сохраняет сопутствующие файлы SQLite WAL, если они присутствуют.

При переходе со старой Windows-службы её нужно остановить и удалить из PowerShell с правами администратора:

```powershell
sc.exe stop CertificateAnalyzerService
sc.exe delete CertificateAnalyzerService
```

Затем установите новую версию и включите пользовательский автозапуск. Проверьте выбранную БД: прежняя служба могла использовать профиль другой учётной записи. Новая установка автоматически такие данные не переносит.

Windows-сборка удаляется через установленные приложения Windows. При установке из исходников используйте `packaging/windows/uninstall.ps1`: он отключает автозапуск и удаляет ярлыки; `-Purge` также удаляет данные профиля по умолчанию.

Для DEB:

```bash
certificate-analyzer worker --stop
sudo apt remove certificate-analyzer
```

Данные пользователя сохраняются. Если включали автозапуск через GUI, перед удалением отключите его в меню «Служба» или командой `autostart disable`.

При установке Linux из исходников `bash packaging/linux/uninstall.sh` останавливает и удаляет пользовательскую службу `certificate-analyzer.service`, прежнюю `cert-analyzer.service` и ярлык. Если служба включена глобально DEB-пакетом, сначала отключите автозапуск в приложении. Флаг `--purge` удаляет профиль по умолчанию. Окружение `.venv` и исходники эти сценарии не удаляют.

## Сборка

Версия пакетов берётся из `pyproject.toml`.

### Windows

Нужны Windows, `uv` и Inno Setup 6:

```powershell
.\packaging\windows\build-installer.ps1
```

Результаты:

- `dist/CertificateAnalyzer/CertificateAnalyzer.exe` — GUI.
- `dist/CertificateAnalyzer/certificate-analyzer-cli.exe` — CLI.
- `dist/installer/CertificateAnalyzer-<версия>-Setup.exe` — установщик.

Без Inno Setup можно собрать только автономную папку приложения:

```powershell
.\packaging\windows\build-installer.ps1 -BundleOnly
```

### Linux

Сборка пакетов выполняется на Linux целевой архитектуры.

**Сборка DEB** (требуются `uv` и `dpkg-deb`):
```bash
bash packaging/linux/build-deb.sh
```
Результат: `dist/linux/certificate-analyzer_<версия>_<архитектура>.deb`.

**Сборка RPM** (требуются `uv` и `rpmbuild`):
```bash
bash packaging/linux/build-rpm.sh
```
Результат: `dist/linux/certificate-analyzer-<версия>-1.<архитектура>.rpm`; для ALT — `-alt1`.

Для ALT Linux собирайте пакет на целевой платформе (или совместимой системе):

```bash
sudo apt-get install rpm-build
bash packaging/linux/build-rpm.sh --distro alt

# Упаковка готовой совместимой Linux-сборки без установки uv:
bash packaging/linux/build-rpm.sh --distro alt --bundle-dir /path/to/bundle --version 0.2.0
```

Профиль ALT выбирается автоматически по `/etc/os-release`. RPM другого
дистрибутива может зависеть от несовместимой версии glibc; профиль пакета
не делает готовые бинарные файлы совместимыми автоматически.

Оба скрипта поддерживают параметр `--bundle-dir <путь>`, позволяющий упаковать уже собранный каталог приложения без повторного запуска PyInstaller. Сборка использует Python 3.11 и включает интерпретатор в пакет; совместимость зависит от системных библиотек машины сборки.

## Разработка и проверки

```bash
uv run pytest
uv run ruff check src tests
```

Для Windows предварительно установите extras `gui` и `windows`; для Linux — `gui`. Тесты используют временные профили, БД и синтетические сертификаты. GUI-проверки, требующие рабочей графической сессии, включаются отдельно:

```bash
# Linux
CERTIFICATE_ANALYZER_GUI_TEST=1 uv run pytest tests/integration/test_gui.py tests/integration/test_gui_ux.py
```

```powershell
# Windows
$env:CERTIFICATE_ANALYZER_GUI_TEST = "1"
uv run pytest tests/integration/test_gui.py tests/integration/test_gui_ux.py
Remove-Item Env:CERTIFICATE_ANALYZER_GUI_TEST
```

Перед релизом проверьте собранное приложение, установку и обновление, автозапуск после повторного входа, уведомления, меню «Служба» и сохранность существующей БД на каждой целевой платформе. Модульные проверки Linux-autostart с подменой systemd не заменяют запуск на реальном Linux.

## Ограничения

Статусы сертификатов и МЧД отражают сроки действия. Приложение не проверяет цепочку доверия, отзыв CRL/OCSP и реестр МЧД; `verification_status` отображается как `NOT_CHECKED`. Объединённая МЧД — неподписанный XML-черновик.

Для открытия файлов через ассоциации ОС разрешены CER, CRT, DER, PEM, XML, PDF, XLSX, DOCX и TXT. Закрытые ключи приложение не извлекает и не хранит.
